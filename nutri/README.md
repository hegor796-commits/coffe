# Любовь-Морковь — бот предзаказа кофейни

> **Про эту папку.** `nutri/` — самодостаточный каркас проекта «Любовь-Морковь»,
> живущий внутри репозитория `coffe` временно, чтобы не смешиваться со старым демо-кофе.
> Позже папку целиком переносим в отдельный репозиторий (`git subtree split` или
> просто копированием содержимого в корень нового репо) — внутри всё готово:
> монорепо `apps/` + `packages/`, `Dockerfile`, workflow'ы в `.github/`. Railway
> здесь не используется. GitHub Actions в этой папке **не запускаются**, пока она
> вложена (Actions читает только корневой `.github/`) — они активируются, когда
> папка станет корнем своего репозитория.


Каркас (skeleton) сервиса предзаказа для кофейни **«Любовь-Морковь»**, построенный
на white-label платформе предзаказа. Одно **Telegram Mini App** с тремя ролями:
**клиент** заказывает, **сотрудник** видит ленту заказов и ведёт их по статусам,
**админ** (владелец) настраивает меню, точки и сотрудников. Мультитенантный —
одна инсталляция обслуживает несколько точек/брендов.

> Историческая справка: код вырос из платформы предзаказа кофе, поэтому во
> внутренних пакетах ещё встречается scope `@coffee/*` и роль «бариста» в UI.
> Это внутренние имена каркаса — бизнес-логика (меню, модификаторы, заказы,
> статусы, роли, бот, уведомления) переиспользуется для Нутри как есть.

Оплата на MVP — **при получении на кассе** (без интеграции с POS). Онлайн-оплата
(ЮKassa с ключами кофейни) заложена в модель как режим тенанта и включается позже.

Документы: [`TECHNICAL_PLAN.md`](./TECHNICAL_PLAN.md) — техплан, [`PLAN.md`](./PLAN.md) — анализ рисков.

## Архитектура

- **`apps/api`** — backend на NestJS: auth по ролям (валидация Telegram initData → JWT),
  меню с модификаторами, заказы с машиной состояний, стоп-лист, приглашения
  сотрудников, Telegram-бот (grammY), WebSocket (socket.io), очереди BullMQ
  (автоотмена непринятых заказов, уведомления).
- **`apps/tma`** — Mini App на React + Vite: роутинг по роли, экраны клиента,
  бариста и админа, корзина, live-статусы через WebSocket.
- **`packages/shared`** — общий код: enum статусов, машина состояний заказа,
  zod-схемы DTO, расчёт цены. Источник истины для фронта и бэка.

Ключевые технические решения (подробнее — в техплане):
`tenant_id` во всех таблицах + RLS; снапшот позиций заказа в JSONB; деньги в
копейках; цена всегда пересчитывается на сервере; push-уведомления бота — основной
канал доставки заказов бариста (Mini App не живёт в фоне), WebSocket — ускоритель.

## Быстрый старт (локально)

Требуется Node 20+, pnpm 10+, Docker (Postgres, Redis, MinIO).

```bash
pnpm install
cp .env.example apps/api/.env        # впишите TELEGRAM_BOT_TOKEN
pnpm infra:up                        # postgres + redis + minio

cd apps/api
pnpm prisma:generate
pnpm prisma db push                  # применить схему (или db:migrate для миграций)
pnpm db:rls                          # включить RLS-политики (defense-in-depth)
pnpm db:seed                         # демо-кофейня «Demo Coffee» (slug: demo)

# два терминала:
pnpm --filter @coffee/api dev        # API на :3000
pnpm --filter @coffee/tma dev        # Mini App на :5173
```

Для теста Mini App с реального телефона поднимите туннель (например
`cloudflared tunnel --url http://localhost:5173`) и укажите его как Web App URL
в настройках бота у @BotFather. Открыть меню демо-кофейни:
`?startapp=demo`.

Сид создаёт владельца и бариста, привязанных к Telegram id из
`SEED_OWNER_TG_ID` / `SEED_BARISTA_TG_ID` (по умолчанию — плейсхолдеры; впишите
свои id, чтобы зайти под этими ролями).

## Деплой (через GitHub, без Railway)

Деплой полностью на GitHub — без Railway и других внешних платформ.
Два workflow в `.github/workflows/`:

- **`ci.yml`** — на каждый push/PR: `pnpm install`, `prisma generate`, сборка
  всех пакетов, typecheck и юнит-тесты. Зелёный CI = каркас собирается.
- **`deploy.yml`** — на push в `main` / рабочую ветку и на теги `v*`: собирает
  Docker-образ (`Dockerfile`) и публикует его в **GitHub Container Registry**
  (`ghcr.io/<owner>/<repo>`). Никаких секретов вручную не нужно — используется
  встроенный `GITHUB_TOKEN`.

Запуск опубликованного образа на любом Docker-хосте (VPS, свой сервер, k8s):

```bash
docker pull ghcr.io/<owner>/<repo>:latest
docker run -d --name nutri -p 3000:3000 --env-file .env \
  ghcr.io/<owner>/<repo>:latest
```

Приложение на старте само применяет схему БД (`prisma db push`) и идемпотентно
сеет демо-данные. Нужны внешние **Postgres** и **Redis** (задаются через
`DATABASE_URL` и `REDIS_URL` в `.env`). Healthcheck — `GET /health`.

### Секреты (важно)

Токен бота и прочие секреты **никогда не коммитятся** в репозиторий. `.env` уже
в `.gitignore`; в git лежит только `.env.example` с плейсхолдерами.

- **Локально:** `cp .env.example apps/api/.env` и впишите реальный
  `TELEGRAM_BOT_TOKEN` в этот `.env`.
- **В проде (Docker-хост):** передавайте секреты через `--env-file .env` или
  переменные окружения контейнера — не внутрь образа.
- **Токен получаете у [@BotFather](https://t.me/BotFather)** (`/newbot` или
  `/mybots → API Token`). Если токен где-то засветился — сразу `Revoke current
  token` в @BotFather и пропишите новый.

## Статус

Реализовано ядро MVP: авторизация по ролям, меню с модификаторами и стоп-листом,
создание заказа с серверным расчётом цены, машина состояний, лента бариста с
кнопками статусов, WebSocket, Telegram-бот и уведомления, автоотмена непринятых
заказов, приглашение сотрудников по ссылке, базовая админка (сотрудники, точки,
стоп-лист). Не реализовано (следующие этапы): онлайн-оплата (ЮKassa), загрузка
фото меню в S3, полноценный редактор меню в админке, биллинг подписки, веб-версия
для клиента, собственный бот тенанта.
