# Любовь-Марковь — платформа предзаказа (много кофеен, много ботов)

> **Про эту папку.** `nutri/` — самодостаточный каркас, живущий внутри
> репозитория `coffe` временно, чтобы не смешиваться со старым демо-кофе.
> Позже целиком переносится в отдельный репозиторий.

## Что реально работает и задеплоено

Проект — **мультитенант-платформа**: один бэкенд обслуживает много кофеен,
у каждой свой Telegram-бот, своё меню, свои сотрудники и заказы.

- **[`design/`](./design/)** — Telegram Mini App (UI): меню, модификаторы,
  корзина, доставка в апартаменты, лента бариста, дашборд владельца.
  Задеплоен на **GitHub Pages** (см. `.github/workflows/pages.yml` в корне
  репозитория) — автодеплой при каждом изменении в этой папке.
- **[`server/`](./server/)** — бэкенд: авторизация по Telegram-подписи,
  серверный расчёт цены, роли, машина состояний заказа, пуш-уведомления
  через бота каждой кофейни, админ-API для добавления новых кофеен/ботов.
  Zero-dependency (`node:http` + `node:sqlite`), деплоится на **Railway**.
  **→ [server/README.md](./server/README.md) — деплой, переменные окружения,
  как добавить новую кофейню.**

Оплата на MVP — при получении на кассе. Доставка — только в апартаменты
здания кофейни (подъезд/этаж/номер), с явным предупреждением клиенту.

## Что в репозитории лежит как справочный материал (не задеплоено)

`apps/api` (NestJS) и `apps/tma` (React) — более полный каркас, из которого
проект стартовал: RLS в Postgres, WebSocket, очереди BullMQ, JWT. Он
**не используется в проде** этого MVP — оказался тяжелее, чем нужно для
одной-двух кофеен на старте (нужны Postgres+Redis, дороже хостинг). Оставлен
как референс на будущее, если платформа вырастет и понадобится: `TECHNICAL_PLAN.md`
и `PLAN.md` описывают именно эту, более тяжёлую архитектуру.

`packages/shared` — общая доменная логика (статусы заказа, машина состояний,
расчёт цены) для `apps/*`; `server/src/domain.js` — независимая, но
согласованная с ней реализация той же логики под лёгкий стек.

## Быстрый старт бэкенда локально

```bash
cd server
DATA_DIR=./data DEMO_BOT_TOKEN=<токен от @BotFather> SEED_OWNER_TG_ID=<твой Telegram id> node src/server.js
npm test        # смоук-тесты (node --test), поднимают реальный сервер
```
Подробности и деплой на Railway — в [`server/README.md`](./server/README.md).

## Секреты (важно)

Токены ботов и админ-секрет **никогда не коммитятся**. `.env`/`server/data/`
в `.gitignore`; в git — только `server/.env.example` с плейсхолдерами.
Токен получаете у [@BotFather](https://t.me/BotFather). Если токен где-то
засветился — сразу `Revoke current token` и впишите новый.

## Статус

Реализовано: мультитенант (много кофеен на одном бэкенде), авторизация по
Telegram-подписи, роли (клиент/бариста/менеджер/владелец — владелец видит и
ленту заказов, и дашборд), меню с модификаторами, серверный расчёт цены,
стоп-лист, самовывоз/доставка в апартаменты с адресом, машина состояний
заказа с пуш-уведомлениями клиенту и сотрудникам, сводка владельца (выручка,
заказы, часы), автотесты бэкенда, CI.

Не реализовано (следующие шаги): полноценная админка для наполнения меню
новой кофейни (пока — прямые SQL/скрипт-сид), онлайн-оплата, приглашение
сотрудников по ссылке (сейчас — через admin API), фото товаров.
